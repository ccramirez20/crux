# Organizer Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire up Better Auth (email+password, gated sign-up via a shared access code) so `apps/web`'s `(organizer)/` route group can be protected, and give `events` an `ownerId` so editing is restricted to the event's creator while viewing stays open to any logged-in account.

**Architecture:** Better Auth's own tables (`user`, `session`, `account`, `verification`) are generated by its CLI directly into `packages/db` — bootstrap-generated first via `--adapter`/`--dialect` flags (no config needed yet), because the server config itself needs those tables to exist before it can reference them for the adapter's `schema` option. `apps/web/lib/auth.ts` exposes a lazy `getAuth()` (not a bare `auth` export) for the same reason `apps/web/lib/db.ts` exposes `getDb()`: this repo already hit and fixed a bug (commit `8a0ffef`) where eager module-scope instantiation crashed `next build` because Next's build-time page-data collection imports route modules without `DATABASE_URL` set. Every new consumer of the auth instance (the API route, the organizer layout) calls `getAuth()` inside its handler/component body, never at module scope.

**Tech Stack:** Better Auth ^1.6.26, Zod ^4.4.3 (input-boundary validation per `CLAUDE.md` convention — this is the sign-up access-code check), `dotenv` (apps/web devDependency, matching `packages/db`'s existing pattern, needed so the Better Auth CLI can load `DATABASE_URL` when it evaluates `apps/web/lib/auth.ts` outside Next's own env loading).

## Global Constraints

- Node 22, TypeScript strict (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, no `any`, no `as`) — from `tsconfig.base.json`.
- Zod at the sign-up input boundary (`CLAUDE.md` convention: "Zod en todo borde de entrada").
- UI text in Spanish (es-CO) — error messages, button labels, page copy.
- `packages/db` stays persistence-only; no business logic lives there.
- Viewing the events list is open to any logged-in account; creating an event sets `ownerId` to the creator; editing/deleting is restricted to matching `ownerId` (enforced in app code, not a DB policy — that enforcement is part of the *next* slice, the create-event screen, not this one. This plan only adds the column and the auth system that makes the check possible).
- No roles/permissions table, no email verification, no password reset flow — all explicitly deferred per the design spec.
- New dependencies: `better-auth`, `zod`, `dotenv` (apps/web only) — all named in the approved design spec.
- Migrations: `packages/db/drizzle/0000_*.sql` has never been applied to a real database, so it is safe to regenerate wholesale in this plan (same reasoning as the prior schema slice's fix round) rather than layer a second migration on top.

- [ ] **Step 4: Write the server config**

Create `apps/web/lib/auth.ts`:
```typescript
import 'dotenv/config';
import { betterAuth } from 'better-auth';
import { drizzleAdapter } from 'better-auth/adapters/drizzle';
import { APIError, createAuthMiddleware } from 'better-auth/api';
import { z } from 'zod';
import { account, session, user, verification } from '@crux/db';
import { getDb } from './db';

const signUpBodySchema = z.object({
  accessCode: z.string().optional(),
});

function createAuth() {
  return betterAuth({
    database: drizzleAdapter(getDb(), {
      provider: 'pg',
      schema: { user, session, account, verification },
    }),
    emailAndPassword: {
      enabled: true,
      requireEmailVerification: false,
    },
    hooks: {
      before: createAuthMiddleware(async (ctx) => {
        if (ctx.path === '/sign-up/email') {
          const { accessCode } = signUpBodySchema.parse(ctx.body);
          if (accessCode !== process.env.ORGANIZER_ACCESS_CODE) {
            throw new APIError('BAD_REQUEST', {
              message: 'Código de acceso inválido.',
            });
          }
        }
      }),
    },
  });
}

// ponytail: cached on globalThis, not module scope — mirrors apps/web/lib/db.ts's
// getDb(). Next's build-time page-data collection imports route modules without
// DATABASE_URL set (see commit 8a0ffef); a module-scope `betterAuth(...)` call
// would crash `next build` the same way the eager db client did.
const globalForAuth = globalThis as unknown as { auth?: ReturnType<typeof createAuth> };

export function getAuth(): ReturnType<typeof createAuth> {
  if (!globalForAuth.auth) {
    globalForAuth.auth = createAuth();
  }
  return globalForAuth.auth;
}
```

import { useState, type FormEvent } from 'react';
import { useRouter } from 'next/navigation';
import { authClient } from '@/lib/auth-client';

export default function SignInPage() {
  const router = useRouter();
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');

- [ ] **Step 2: Sign-up page**

Create `apps/web/app/sign-up/page.tsx`. This uses a plain `fetch` instead of `authClient.signUp.email(...)` deliberately — `accessCode` is read by the server's `before` hook straight from the raw request body and is never persisted as a real column (see the design spec), so it isn't a field Better Auth's typed client needs to know about:
```typescript
'use client';

import { useState, type FormEvent } from 'react';
import { useRouter } from 'next/navigation';
import { z } from 'zod';

const errorBodySchema = z.object({ message: z.string() }).partial();

export default function SignUpPage() {
  const router = useRouter();
  const [name, setName] = useState('');
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [accessCode, setAccessCode] = useState('');
  const [error, setError] = useState<string | null>(null);
  const [isSubmitting, setIsSubmitting] = useState(false);

  async function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    setError(null);
    setIsSubmitting(true);
    const response = await fetch('/api/auth/sign-up/email', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ name, email, password, accessCode }),
    });
    setIsSubmitting(false);
    if (!response.ok) {
      const rawBody: unknown = await response.json().catch(() => null);
      const parsed = errorBodySchema.safeParse(rawBody);
      setError((parsed.success && parsed.data.message) || 'No se pudo crear la cuenta.');
      return;
    }
    router.push('/');
  }

  return (
    <main className="flex min-h-screen items-center justify-center">
      <form onSubmit={handleSubmit} className="flex w-full max-w-sm flex-col gap-4">
        <h1 className="text-2xl font-semibold">Crear cuenta de organizador</h1>
        <input
          type="text"
          placeholder="Nombre"
          value={name}
          onChange={(event) => setName(event.target.value)}
          required
          className="rounded border px-3 py-2"
        />
        <input
          type="email"
          placeholder="Correo"
          value={email}
          onChange={(event) => setEmail(event.target.value)}
          required
          className="rounded border px-3 py-2"
        />
        <input
          type="password"
          placeholder="Contraseña"
          value={password}
          onChange={(event) => setPassword(event.target.value)}
          required
          minLength={8}
          className="rounded border px-3 py-2"
        />
        <input
          type="text"
          placeholder="Código de acceso"
          value={accessCode}
          onChange={(event) => setAccessCode(event.target.value)}
          required
          className="rounded border px-3 py-2"
        />
        {error && <p className="text-sm text-red-600">{error}</p>}
        <button
          type="submit"
          disabled={isSubmitting}
          className="rounded bg-black px-3 py-2 text-white disabled:opacity-50"
        >
          Crear cuenta
        </button>
      </form>
    </main>
  );
}
```
